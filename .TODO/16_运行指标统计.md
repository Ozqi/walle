# 运行指标统计 TODO

> 由 Claude Opus 5 于 2026-09-22 阅读 `AGENTS.md`、`.spec/agent.md`、`.spec/model-config.md`、`.spec/runtime.md`、`internal/agent/*.go`、`internal/daemon/*.go`、`internal/tui/*.go`、`internal/utils/tokenBudget.go` 后整理。
> 范围：为普通 Agent run 增加 token 开销、首 token 等待时长、整体等待时长和输出速度统计。

## 背景

当前已有基础 token usage 链路：LLM callback/`ResponseMeta.Usage` -> `TokenBudget` -> daemon `ProcessEvent` -> TUI footer。它能显示最近 prompt token、会话累计 token 和 context window，但还缺少面向用户判断模型体验的运行指标：本轮花了多少 token、等待了多久、首 token 等待多久、输出速度是多少。

## 目标

- [ ] 在每一轮普通输入结束时，展示本轮运行指标摘要。
- [ ] TUI 运行中能显示轻量实时指标，不因高频 token 造成卡顿。
- [ ] 指标从 runtime/agent 事实源产生，daemon 只透传，TUI 只展示。
- [ ] 支持流式和非流式模型；provider 未返回 usage 时也要优雅降级。

## 指标定义

| 指标 | 定义 | 备注 |
| --- | --- | --- |
| `prompt_tokens` | provider 返回的本次 prompt/input tokens | 没返回时显示 `-`，不要本地估算冒充真实值 |
| `completion_tokens` | provider 返回的本次 completion/output tokens | 没返回时显示 `-`；可另行记录本地输出字符数 |
| `total_tokens` | provider 返回的本次 total tokens；缺失时用 prompt + completion | 已有 `TokenBudget.AddUsage` fallback，可复用 |
| `session_total_tokens` | 当前 Runtime 生命周期累计 total tokens | 继续由 `TokenBudget` 维护 |
| `wait_ms` | 从用户提交被 Agent 接收到，到 run 进入终态的耗时 | 包含模型、工具、后续 ReAct turn |
| `first_token_ms` | 从本轮开始到第一个 assistant/reasoning 文本 chunk 到达 | 非流式没有真实首 token，显示 `-` 或标记 `non-stream` |
| `output_chars` | 本轮 assistant 正文 + thinking 文本字符数 | 作为 usage 缺失时的速度参考，不等同 token |
| `tokens_per_sec` | completion_tokens / 从首 token 到最后 token 的秒数 | completion_tokens 缺失时不显示 |
| `chars_per_sec` | output_chars / 从首 token 到最后 token 的秒数 | provider usage 缺失时仍可显示 |

## 实现计划

### 1. Agent 层增加 run stats 事实源

- [ ] 在 `internal/agent` 增加小型结构，例如 `RunStats`：记录 `StartedAt`、`FirstTokenAt`、`LastTokenAt`、`FinishedAt`、`OutputChars`、`Usage`。
- [ ] 在 `RunStreamWithOptions` 每轮入口初始化 stats，首个非空 assistant/reasoning chunk 到达时写 `FirstTokenAt`，每个输出 chunk 累加 `OutputChars` 并更新 `LastTokenAt`。
- [ ] 流式路径在合并 `ResponseMeta.Usage` 后写入 stats；非流式路径从 `Generate` 返回消息的 `ResponseMeta.Usage` 写入 stats。
- [ ] 工具调用期间不要重置本轮 stats；多次 ReAct 模型调用的 usage 应按本轮累计，等待时长覆盖完整 run。
- [ ] 结束、错误、取消都要设置 `FinishedAt`，并把可用 stats 通过现有 callback/event 出口传出。

### 2. Runtime/daemon 事件透传

- [ ] 扩展 daemon `ProcessEvent`，增加可选 `RunStats` 字段或扁平字段：`wait_ms`、`first_token_ms`、`output_chars`、`completion_tokens`、`tokens_per_sec`、`chars_per_sec`。
- [ ] `snapshotStateEvent` 保持轻量，只带当前累计 usage；本轮 stats 只在 run 终态或低频 status event 中发送。
- [ ] attach/replay 时不要把旧 stats 当作新的 running 状态；历史里如果需要保留，只作为 system recap 展示。
- [ ] public `runtime` SDK 如已有事件 DTO，需要同步补可选字段，保持零值兼容。

### 3. TUI 展示

- [ ] footer 运行中显示低频 live 指标：例如 `running 4s │ first 1.2s │ 38 tok/s`；没有 completion token 时显示 `running 4s │ 420 chars/s`。
- [ ] run 结束后在 assistant 输出后追加一行轻量 system/meta：例如 `stats: 1.3s first, 8.7s total, 214 out tok, 24.6 tok/s, 3.1k total tok`。
- [ ] 窄屏下优先保留总耗时和速度，token 细节可截断，不能撑破 footer。
- [ ] 继续复用现有 token 渲染节流，禁止每个 token chunk 触发完整 footer 重排。

### 4. 日志与文档

- [ ] debug log 可记录 stats，但不得记录 API key、OAuth token、account id 或完整 prompt。
- [ ] 更新 `.spec/agent.md` 的 token 统计范围，说明新增等待时长和输出速度。
- [ ] 更新 `.spec/model-config.md` 的 `TokenBudget` 说明：区分会话累计 token 与单轮 run stats。
- [ ] 更新 `doc/interface/cli.md` 或 `doc/interface/logger.md`，说明用户能看到哪些统计、哪些 provider 可能不返回 token usage。

## 边界与取舍

- 不做本地 tokenizer 精确估算；provider 没返回 usage 时只显示字符数和耗时。
- 不把价格表硬编码进第一版；“token 开销”先指 token 消耗，不计算人民币/美元成本。后续如要价格，需要单独 TODO：provider/model 价格配置、缓存 token 价格、汇率和过期策略。
- 不把 stats 写成独立持久化数据库；session JSONL 中如已有 event replay，可保留终态 system/meta 文本即可。
- 不为每个 provider 写专用逻辑；优先使用 Eino/Codex adapter 已返回的 `ResponseMeta.Usage`。
